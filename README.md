# VFS: Busy inodes after unmount of a nilfs2 mount (kernel BUG at fs/super.c:731)

Syzkaller-found bug on Linux v7.4-rc2, reproduced and verified on the same
kernel build. Two verified reproducers are provided:

- **C reproducer** (`reproducer/repro.cprog`): compile with
  `gcc -x c -O1 -static -o repro reproducer/repro.cprog` (the `-x c` is
  needed because of the `.cprog` extension) in a suitable Linux build
  environment, copy the resulting binary into the guest and run it as root.
  Verified on a fresh VM: the kernel BUG fires 113.9 seconds after guest
  boot (single attempt, 1/1 successes). See `logs/c-verification/`.
- **syz reproducer** (`reproducer/repro.prog`): run with
  `syz-execprog -procs=1 -threaded -repeat=0 -executor ./syz-executor repro.prog`.
  Verified on a fresh VM: the kernel BUG fires 244.6 seconds after guest
  boot (single attempt, 1/1 successes). See `logs/verification-serial.log`.

Timings below are seconds since guest boot, not wall-clock since the start
of the command. The two reproducers trigger the same crash, but their call
sequences are not identical (the C reproducer was generated by syzkaller's
reproducer pipeline from a slightly different minimisation).

## Summary

On unmount of a nilfs2 filesystem, `generic_shutdown_super()` finds inodes
still present on the superblock's inode list:

```
NILFS (loop5): disposed unprocessed dirty file(s) when stopping log writer
VFS: Busy inodes after unmount of loop5 (nilfs2)
------------[ cut here ]------------
kernel BUG at fs/super.c:731!
Oops: invalid opcode: 0000 [#1] SMP KASAN NOPTI
CPU: 3 UID: 0 PID: 10340 Comm: syz-executor Not tainted 7.4.0-rc2-kernsight-kasan #1 PREEMPT(full)
RIP: 0010:generic_shutdown_super+0x305/0x3a0 fs/super.c:731
Call Trace:
 kill_block_super+0x49/0x130 fs/super.c:1852
 deactivate_locked_super+0xc0/0x130 fs/super.c:558
 deactivate_super+0xb9/0xd0 fs/super.c:582
 cleanup_mnt+0xbc/0x160 fs/namespace.c:1396
```

The `CHECK_DATA_CORRUPTION(... "VFS: Busy inodes after unmount of %s (%s)")`
in `generic_shutdown_super()` (fs/super.c:731) fires. The guest kernel is
built with `CONFIG_BUG_ON_DATA_CORRUPTION=y`, so this check compiles to a
`BUG()`, raising a kernel BUG/Oops; the guest also runs with `oops=panic`
on the kernel command line, which escalates it to a kernel panic. (The
guest additionally sets `panic_on_warn=1`, but that is not what turns this
check into a BUG.)

Immediately before the BUG, the nilfs2 log writer reports:

```
NILFS (loop5): disposed unprocessed dirty file(s) when stopping log writer
```

In the captured logs the two messages appear in this order on the way down;
whether the log-writer shutdown is the direct cause of the residual busy
inodes, or both are effects of the same underlying state, has not yet been
confirmed. Residual busy inodes after unmount means subsequent accesses can
touch a freed superblock/inode — a potential use-after-free risk (this is
why syzkaller titles the report "VFS: Busy inodes after unmount
(use-after-free)"); a use-after-free itself has not been observed in these
runs.

## How to reproduce

Environment used: Debian trixie x86_64 guest (6 GiB RAM, 4 vCPU, KVM),
kernel built from v7.4-rc2 with CONFIG_KASAN=y, CONFIG_PROVE_LOCKING=y,
CONFIG_BUG_ON_DATA_CORRUPTION=y (CONFIG_NILFS2_FS=y), booted with
`oops=panic` and `panic_on_warn=1`. See `environment.txt` for the exact
QEMU command line and `kernel.config` for the configuration.

C reproducer:

```sh
# on a suitable Linux build host:
gcc -x c -O1 -static -o repro reproducer/repro.cprog
# copy the `repro` binary into the guest, then run as root:
./repro
```

Verified on a fresh VM: the kernel BUG at fs/super.c:731 fires 113.9
seconds after guest boot (1 attempt, 1 success). The syzkaller reproducer
pipeline independently confirmed the C reproducer as well
(`logs/c-verification/manager-c-repro-report.txt`). The stable success rate
over multiple runs has not been measured yet — a single fresh-VM attempt
was performed for this archive, and it succeeded.

syz reproducer:

```sh
# in the guest, as root:
syz-execprog -procs=1 -threaded -repeat=0 -executor ./syz-executor repro.prog
```

Verified on a fresh VM: the kernel BUG at fs/super.c:731 fires 244.6
seconds after guest boot (1 attempt, 1 success). Console logs:
`logs/crash-serial-excerpt.txt` and `logs/verification-serial.log`.

`reproducer/repro.prog` is a single self-contained syzkaller program (5
calls: it mounts a crafted nilfs2 image via `syz_mount_image$nilfs2`,
creates a file and issues `NILFS_IOCTL_CLEAN_SEGMENTS` on it). The syzkaller
build used is commit `853b104bb454141a5b0fc0e4218ec78e9f34ffb1` (see
`environment.txt`); the command above (`-procs=1 -threaded -repeat=0`) is
the exact invocation used in the successful verification run. The
minimized program's own options header requests `Threaded:true
Repeat:true RepeatTimes:0 Procs:8`.

`reproducer/repro.cprog` was generated by syzkaller's reproducer pipeline
and verified by running the compiled binary in a fresh VM. It performs a
similar — but not identical — sequence to `repro.prog`: the syzkaller
executor tears down its per-run working directory with a forced
`umount2(..., MNT_FORCE)` between program iterations, and the C
reproducer's generated code includes that same teardown, which is where
the crash surfaces.

## Notes for maintainers

- What is confirmed: at unmount time inodes remain on the superblock's
  inode list while the nilfs2 log writer reports it disposed unprocessed
  dirty files; the two events are adjacent in the logs.
- Not yet confirmed: whether the log-writer shutdown is the cause of the
  residual busy inodes. Correlating the nilfs2 log-writer stop path with
  the VFS unmount invariant check is the natural next step.
- We can provide the kernel image, additional crash instances or raw
  artifacts on request.
